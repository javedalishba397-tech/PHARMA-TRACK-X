# Implementation Plan - PharmaTrack-X v1.0

PharmaTrack-X is an Expiry-Risk and Demand-Uncertainty-Aware Pharmacy Inventory Decision Support System designed according to the Software Requirement Specification (SRS) v1.0. It provides full pharmacy operations management (medicines, batches, suppliers, purchase orders, sales/billing with automatic FEFO allocation, customers, stock alerts, and reporting) integrated with an explainable statistical demand-uncertainty and expiry-risk decision support engine.

## User Review Required

> [!IMPORTANT]
> - **Database Support**: As specified in Section 2.5 (C-1) and Section 4.3.8, PostgreSQL is the primary database (with standard SQL via SQLAlchemy ORM). To enable immediate, zero-configuration local development and testing without requiring manual database service provisioning, the system will support SQLite out-of-the-box as the default local connection, while remaining 100% plug-and-play compatible with PostgreSQL (configured via `DATABASE_URL=postgresql://...`).
> - **Human in Control**: Every recommendation generated by the decision support engine will be created as `Pending` and requires explicit Pharmacist approval before any order or batch priority change is committed (C-3, FR-46, NFR-S2).

### 1. Decision Module Package (`pharmatrack_decision` / `decision_module`)
*Requirement: Section 5.4 - "The decision module shall be a separate Python package with its own tests so that it can be reused in another inventory system."*

#### [NEW] `backend/packages/decision_module/setup.py` & `pyproject.toml`
- Package definition for standalone installation and reuse.

#### [NEW] `backend/packages/decision_module/decision_module/forecaster.py`
- Implements FR-38, FR-39, FR-40:
  - Aggregates daily sold quantities.
  - Computes baseline statistical demand forecast over the horizon (default 30 days) with confidence intervals (default 80%).
  - Computes coefficient of variation ($CV = \sigma / \mu$).
  - Assigns confidence level: `Low` if history < `min_history_days` (30) or $CV > max\_daily\_cv$ (1.0); else `Medium` or `High`.
  - Adjusts forecast bounds conservatively (wider range as history decreases or variability increases).

#### [NEW] `backend/packages/decision_module/decision_module/engine.py`
- Implements FR-41, FR-42, FR-43, FR-44, FR-45, Table 3.20 & Figure 3.6:
  - Strict rule evaluation order:
    1. **Review**: history < 30 days, or confidence == Low, or new medicine, or no forecast.
    2. **Reorder**: usable stock cover < supplier lead time and no pending PO arriving in time. Calculates `suggested_qty = upper_bound_demand(horizon + lead_time) - usable_stock - pending_qty`.
    3. **Prioritize (FEFO)**: projected unsold quantity at expiry > 0 (using lower-bound demand) AND days to expiry $\le$ `near_expiry_threshold` (90 days).
    4. **Hold**: stock adequate, no action needed.
  - Computes composite Risk Score (0-100) using weighted formula:
    $$\text{Risk} = w_{\text{expiry}} \times \text{ExpiryRisk} + w_{\text{stockout}} \times \text{StockoutRisk} + w_{\text{uncertainty}} \times \text{Uncertainty}$$
  - Generates plain-language explanation containing all 5 mandatory inputs: current stock, days to expiry, expected demand & range, confidence level, supplier lead time, plus rule rationale.

#### [NEW] `backend/packages/decision_module/tests/`
- Dedicated unit tests for forecasting accuracy, confidence labeling, back-testing validation ($\ge 70\%$ coverage check as required by AC-6), and decision rule firing order.

### 2. Backend Application (`backend/`)
*Built with FastAPI, SQLAlchemy 2.0, Pydantic v2, ReportLab, and bcrypt.*

#### [NEW] `backend/app/core/config.py`
- System configuration, JWT secrets, database connection string, session timeout (15 mins), lockout settings.

#### [NEW] `backend/app/core/security.py`
- Password hashing with bcrypt (SEC-3).
- JWT token creation and verification with 15-minute inactivity timeout (FR-06, SEC-6).
- Account lockout logic (5 failed attempts $\rightarrow$ 15-minute lockout) (FR-01, SEC-6).

#### [NEW] `backend/app/db/session.py` & `backend/app/db/base.py`

- `batches.py`: batch_id, medicine_id, po_item_id, batch_number, expiry_date, received_date, qty_received, qty_remaining, purchase_price, status (Active, Near-Expiry, Expired, Depleted, Written-Off), sell_first.

- `decision_logs.py`: decision_id, recommendation_id, user_id, decision (Approved, Rejected, Modified), final_action, final_qty, comment, decided_at.
- `system_settings.py`: setting_key, setting_value, description, updated_by, updated_at (with Appendix A.4 defaults).
- `audit_logs.py`: log_id, user_id, action, entity, entity_id, result, ip_address, logged_at (SEC-7).

#### [NEW] `backend/app/services/`
- `auth_service.py`: login, account lockout tracking, password change with 8+ char / letter+digit validation (FR-05).
- `medicine_service.py`: duplicate prevention, partial search, deactivation logic.
- `batch_service.py`: batch registration, future expiry validation, daily status updates (Active $\rightarrow$ Near-Expiry $\rightarrow$ Expired $\rightarrow$ Depleted).
- `supplier_service.py`: FR-14 observed average lead time calculation based on $\ge 3$ completed deliveries.
- `purchase_service.py`: PO creation, overdue flag calculation, cancellation rules, full/partial receiving into batches.
- `sale_service.py`: Atomic FEFO allocation (FR-22), strict block on expired batches (FR-23), prescription warning flag, maximum discount validation, bill voiding with full stock restoration (FR-27).
- `stock_service.py`: Low-stock alert computation, near-expiry alert computation, write-off with audit trail, quantity adjustments.
- `recommendation_service.py`: Automated daily execution & on-demand execution, approval workflow (Approve $\rightarrow$ creates draft PO or flags "Sell First", Reject, Modify), superseding pending recommendations.
- `report_service.py`: Aggregations for Sales, Stock & Expiry, Purchases, Wastage, Recommendations.
- `pdf_service.py`: ReportLab generation for Invoices, Purchase Orders, and Reports.
- `csv_service.py`: Standard CSV export generation for all reports.

#### [NEW] `backend/app/api/`
- REST API routers organized by resource with RBAC dependency enforcement (Table 3.5).

#### [NEW] `backend/app/scripts/seed_demo_data.py`

  - Multiple batches per medicine (Active, Near-Expiry, Expired, Depleted).
  - 60+ days of realistic daily sales transactions to feed the demand forecaster.
  - Pending purchase orders and historical customer records.

## Verification Plan

### Automated Tests
1. Run pytest across the complete test suite:
   ```powershell
   .\venv\Scripts\pytest backend/tests -v
   ```
2. Verify decision module standalone tests:
   ```powershell
   .\venv\Scripts\pytest backend/packages/decision_module/tests -v
   ```
3. Run the back-test evaluation script to verify AC-6 ($> 70\%$ coverage).
4. Run the 50-attempt expired batch rejection test to verify AC-2 ($100\%$ rejection).

### Manual Verification
1. Start the backend with Uvicorn and frontend with Vite.
2. Log in as Sales Clerk: test POS billing with barcode scanner emulation, observe FEFO allocation and prescription warning; test that restricted tabs (Purchases, Recommendations, Settings) are hidden/blocked.
3. Log in as Pharmacist: inspect Recommendations, view explanation with 5 variables, approve a Reorder recommendation (verify draft PO created), approve a Prioritize recommendation (verify "Sell First" tag on POS), and void a bill (verify stock restoration).
4. Log in as Administrator: configure system parameters, inspect audit logs, generate and export PDF/CSV reports.
